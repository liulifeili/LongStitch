# 构建与发布

## 前置条件

只要 **\.NET 8 SDK**。本项目**零 NuGet 依赖**——不需要联网还原任何第三方包。

```powershell
dotnet --version    # 需要 8.x
```

为什么刻意零依赖：
1. 协作环境里经常拉不到 `nuget.org`，依赖还原一旦失败，整轮构建就卡在那儿；
2. 项目要发给别人、上架 GitHub，`git clone` + `dotnet build` 必须一次成功；
3. 更关键的是**精度**：PNG 编解码自己实现之后，"导出字节没被偷偷改动"才是可证明的，
   而不是"希望第三方库不做色彩管理"。

## 日常开发

```powershell
dotnet build                                   # 三个工程，应为 0 警告 0 错误
dotnet run --project checks/LongStitch.Checks   # 精度电池，退出码 0 = 全绿
dotnet run --project src/LongStitch.App         # 打开主程序
```

`build.ps1` 把上面三件事串成一条命令，任一步失败即退出码非 0。

## 发布：绿色版与安装版（第六十四改起）

发布分两种形态，都基于**自包含文件夹**（不再做单文件）：

```powershell
.\build.ps1 -Publish -Zip          # 绿色版：publish\ 文件夹 + out\LongStitch-win-x64-vX.Y.Z.zip
.\build.ps1 -Publish -Installer    # 安装版：out\LongStitch-installer-vX.Y.Z.exe（需要 Inno Setup 6）
```

`-Publish` 等价于：

```powershell
dotnet publish src/LongStitch.App -c Release -r win-x64 --self-contained -o publish
New-Item -ItemType Directory -Force -Path publish/data
```

**为什么放弃单文件**：自包含单文件每次启动都要把原生库自解压到 `%TEMP%\.net\`——
这个目录永远在 C 盘，用户把程序装/解到任何别的盘都拦不住，与"少在 C 盘堆文件"的要求直接冲突。
文件夹发布没有任何启动期写入，启动更快，也天生不怕中文目录。

**数据跟盘**：两种包里都放一个空的 `data\` 文件夹。程序发现 exe 旁有 `data\`，
就把偏好（`preferences.txt`）、最近项目（`recent.txt`）、诊断日志（`logs\`）全部落到里面；
没有 `data\` 则维持 Windows 惯例（`%APPDATA%` / `%LOCALAPPDATA%` 下的 LongStitch 子目录，
老用户升级后行为不变）。装/解到哪个盘，数据就在哪个盘；删掉整个目录 = 数据一并清干净。

绿色版：解压 zip 到任何目录（含中文目录）直接运行，无需安装 .NET。
安装版：Inno Setup 6 编译（`installer/LongStitch.iss`），简体中文界面，默认按当前用户
装到 `%LOCALAPPDATA%\Programs\LongStitch`（不需要管理员权限），安装者可改成任意盘；
卸载器不删 `data\`（那是用户数据）。

## GitHub Actions

`.github/workflows/build.yml` 每次 push 跑：build → 电池 → 上传产物到 workflow artifacts。
**该工作流未在本地验证过**（需要真实 GitHub 环境跑一次），第一次推上去请留意 Actions 页。

## 版本与产物命名

版本号在 `src/LongStitch.App/LongStitch.App.csproj` 的 `<Version>` 里，
发布新版本时同步改 `installer/LongStitch.iss` 的 `AppVersion` 与 `README.md`、`docs/` 里引用到版本的地方。

Release 建议附：
- `LongStitch-win-x64-vX.Y.Z.zip`（绿色版，自包含文件夹）
- `LongStitch-installer-vX.Y.Z.exe`（安装版）
- 一段"精度承诺范围"的说明（PNG 无损可证；JPEG 几何精确但有损；见 docs/精度红线.md）

## 已知构建注意事项

| 现象 | 原因与处理 |
| --- | --- |
| `error CS0117: ToolStripButton 未包含 TooltipText` | 属性名是 `ToolTipText`（两个 T），不是 `TooltipText` |
| 菜单被顶栏盖住 / 菜单跑到 y=58 | WinForms 停靠是"后加入的占外侧"，`Controls.Add` 顺序见 `MainForm` 构造函数注释 |
| 主窗口构造时抛 `InvalidEnumArgumentException` | `ToolStripMenuItem.ShortcutKeys` 不接受裸 `Keys.Escape`，非字母数字键必须带修饰键 |
| 控制台中文输出花屏 | Checks 已设 `Console.OutputEncoding = UTF8`；重定向到文件失败时会静默跳过 |

## 测试怎么读

```powershell
dotnet run --project checks/LongStitch.Checks -- --only export
```

分组含义：

| 组 | 在量什么 |
| --- | --- |
| `blit` | 整数搬运原语：越界联立裁剪、分块=整块、合成公式 |
| `png` | 自研 PNG 编解码：往返无损、坏 CRC 被拒、16 位/隔行如实上报、`eXIf` 方向两种端序读对且坏块退回 1、GDI+ 交叉核对 |
| `layout` | 布局引擎：紧接排列、1 像素位移精确、切分不改变可见像素、撤销、源图丢失安全 |
| `match` | 重叠匹配：找回已知重叠、分辨 1 像素、固定栏陷阱、多候选降级 |
| `cleanup` | 清理（第十四轮末次起只剩滚动条一项）：检出并抹除滚动条、无滚动条时一像素都不动、**重复运行幂等**；「统一状态栏 / 底部固定栏 / 时间替换」那几格已随功能作废，见 README「第四十改」 |
| `export` | 导出：分块=整块逐字节、分段覆盖完整并避开拼缝、取消不留半成品、超限不静默压缩 |
| `ui` | 冒烟：控件树能构造、停靠几何正确、面板来回切换不炸（**不显示窗口**） |
| `guard` | 守卫的守卫：故意注入缺陷，要求必须变红 |

**"跳过"不算通过**，会在末尾单独计数——没跑的检查不许被省略成看起来跑过了。
